Contexto da mensagem que disparou o handler (runtime only).

```js
ctx.msg.id;            // string - ID único da mensagem
ctx.msg.timestamp;     // integer - Timestamp UNIX
ctx.msg.body;          // string - texto completo
ctx.msg.type;          // string - "chat" | "image" | "video" | "audio" | ...
ctx.msg.fromMe;        // boolean - true se enviada pelo próprio bot
ctx.msg.sender;        // string|null - LID-canônico de quem enviou (@lid)
ctx.msg.senderPn;      // string|null - mesmo remetente em formato telefone (@c.us)
ctx.msg.senderName;    // string - nome de exibição
ctx.msg.command;       // string - primeira palavra, sem prefixo, normalizada
ctx.msg.args;          // string[] - palavras após o comando
ctx.msg.hasMedia;      // boolean - true se a mensagem tiver alguma mídia (imagem, vídeo, áudio, documento)
ctx.msg.isGif;         // boolean - true se a mensagem tem um GIF
ctx.msg.hasReply;      // boolean - true se é resposta a outra msg
ctx.msg.hasPrefix;     // true se começa com CMD_PREFIX (do manybot.toml)
ctx.msg.hasMention;    // true se a mensagem menciona alguém (@)
ctx.msg.hasBotMention; // true se a mensagem menciona o próprio bot
ctx.msg.mentionedJid;  // string[] - JIDs mencionados, PN já resolvido pra @lid quando conhecido
```

Funções:

```js
ctx.msg.is(cmd: string);                        // boolean - cmd: prefixo + string normalizada (ex. "!ping")
ctx.msg.downloadMedia(opts?: {asMp4?: boolean}) // Promise<{ mimetype: string; data: string}|null> - Baixa mídia se houver, retorna o caminho junto do mimetype.
                                                // a opção 'asMp4', se true, baixa em formato MP4

ctx.msg.getReply()                              // Promise<WAMessageContext | null> - Retorna o objeto da mensagem no qual msg está respondendo. Ou null se não estiver respondendo nenhuma.
ctx.msg.reply.text/image/video/audio/file/poll  // Mesma coisa que um ctx.send, mas manda respondendo a mensagem msg
ctx.msg.react(emoji: string)                    // Promise - Reage a mensagem com um emoji. Retorna erro em RUNTIME se colocar um caractere que não é emoji ou mais de um
                                                // use react("") (vazio) para remover uma reação

ctx.msg.delete(forEveryone?: false | true)      // Promise - Deleta a mensagem
                                                // a opção forEveryone deleta a mensagem para todos, por padrão é `true`

ctx.msg.edit(text: string)                      // Promise - Edita a mensagem (somente se ela for sua)
ctx.msg.pin()                                   // Deprecated. Infelizmente esse aqui não funciona, está aqui como resíduo da migração do whatsapp-web.js para o Bailyes. Quem sabe num futuro próximo
ctx.msg.getContact()                            // Promise<NormalizedContact | null> - Pega o objeto do contato de quem enviou a mensagem
```

> **`sender` agora é LID-canônico, não `@c.us`:** desde a migração pro Baileys v7 (LID-aware),
> `ctx.msg.sender` devolve o JID `@lid` do remetente — `null` quando o ManyBot ainda não aprendeu
> o LID desse contato (comum no primeiro contato). **Não há mais fallback silencioso pra
> `@c.us`.** Se seu plugin ainda compara `sender` contra números de telefone (ex: contra `CHATS`
> no `manybot.toml`, ou config baseada em número), use `ctx.msg.senderPn` — a mesma pessoa, no
> formato `@c.us`, também `null` quando não disponível. Trate os dois campos como possivelmente
> `null` antes de comparar.
>
> **Formato de ID em outros lugares:** conversas privadas (`ctx.chat.id`, `CHATS` no
> `manybot.toml`) continuam normalizadas pro sufixo `@c.us`, e grupos continuam com `@g.us` — essa
> parte não mudou. A mudança pra LID é específica de identidade de **pessoa** (`ctx.msg.sender`,
> `id` no [objeto de contato](/docs/api/ctx-contacts/#objeto-de-contato-normalizado)), não de
> **conversa**. Use sempre `@c.us` ao montar ou comparar um ID de conversa privada manualmente —
> um valor com `@s.whatsapp.net` (o formato nativo do Baileys) não vai bater numa comparação
> `===` com `ctx.chat.id`.

### Detectando comandos

```js
// Mensagem: "!ping"  (CMD_PREFIX = "!")
if (ctx.msg.is("ping")) {
  await ctx.send.text("pong!");
}
```

O `msg.is` já normaliza o texto internamente, isso significa que `msg.is("ola")` retorna `true` para "!olá", "!Olá", "!OLÁ" e outras variações.

### Lendo argumentos

```js
// Mensagem: "!video https://youtube.com/watch?v=..."
const url = ctx.msg.args[0];
if (!url) {
  await ctx.msg.reply.text("Informe uma URL.");
  return;
}
```

### Respondendo com quote

`ctx.msg.reply` é um sender completo — mesmos métodos de [`ctx.send`](/docs/api/ctx-send/), mas
citando a mensagem original:

```js
await ctx.msg.reply.text("Aqui está sua resposta!");
await ctx.msg.reply.image("/tmp/foto.jpg", "Sua imagem.");
```

### Baixando mídia

```js
if (ctx.msg.hasMedia) {
  const media = await ctx.msg.downloadMedia(); // { mimetype, data(base64) } | null
  if (!media) return void await ctx.msg.reply.text("Não consegui baixar.");
  const buf = Buffer.from(media.data, "base64");
}
```

### Mensagem citada

```js
if (ctx.msg.hasReply) {
  const quoted = await ctx.msg.getReply(); // objeto igual ao ctx.msg | null
  console.log(quoted?.senderName, quoted?.hasMedia, quoted?.body);
}
```

`getReply()` devolve um objeto **na mesma shape do `ctx.msg`** (`body`, `type`, `sender`,
`senderName`, `hasMedia`, `isGif`, `downloadMedia()`, `hasPrefix`, `command`, `args`, `reply`,
etc.) — não é o formato bruto do Baileys. Isso quer dizer que dá sim pra usar
`quoted.hasMedia`/`quoted.downloadMedia()`/`quoted.reply.text(...)` direto:

```js
if (ctx.msg.hasReply) {
  const quoted = await ctx.msg.getReply();
  if (quoted?.hasMedia) {
    const media = await quoted.downloadMedia(); // baixa a mídia da mensagem citada
  }
}
```

> Não existe campo `quoted.pushName` nem `quoted.message` — use `quoted.senderName` (igual ao
> `ctx.msg.senderName`) e, se precisar da estrutura crua do Baileys por algum motivo específico,
> não tem atalho público pra isso hoje.

> `getReply()` não faz nenhuma chamada de rede — ele só reprocessa dados que a mensagem atual já
> trouxe consigo (a citação vem embutida em `contextInfo`). Não tem delay associado a ele.

> `quoted.senderName` **sempre** cai pro número de telefone — o protocolo de citação do WhatsApp
> (`contextInfo`) não carrega o `pushName` de quem mandou a mensagem original, só o JID. Isso é
> diferente do `ctx.contacts.get()`/`ctx.msg.getContact()`, que de fato aprende e guarda o nome
> real ao vivo (veja a nota em [ctx.contacts](/docs/api/ctx-contacts/)) — mas `getReply()` não
> passa por esse caminho, então não se beneficia disso.

### Contato do remetente

`ctx.msg.getContact()` resolve `@lid` automaticamente — prefira isso a
`ctx.contacts.get(ctx.msg.sender)` dentro de um handler. Mesma shape de
[objeto de contato](/docs/api/ctx-contacts/#objeto-de-contato-normalizado), incluindo o mesmo
comportamento de devolver `null` pra alguém que o bot ainda não "viu" mandar mensagem (veja a
nota em [ctx.contacts](/docs/api/ctx-contacts/)) — trate esse caso antes de usar `contact.mention`
ou qualquer outro campo:

```js
const contact = await ctx.msg.getContact();
if (!contact) return; // ainda não temos dados desse contato
await ctx.msg.reply.text(`oi ${contact.mention.text}`, contact.mention);
```

### Detectando menções

```js
if (ctx.msg.hasBotMention) {
  await ctx.msg.reply.text("Me chamou?");
}

if (ctx.msg.hasMention) {
  for (const jid of ctx.msg.mentionedJid) {
    ctx.log.info(`Mencionado: ${jid}`); // já em @lid quando resolvido
  }
}
```

### Evitando loops

O bot recebe as próprias mensagens também:

```js
export default async function (ctx) {
  if (ctx.msg.fromMe) return;
  // ...
}
```
